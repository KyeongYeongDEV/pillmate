# Context Hygiene — compact vs clear (2026-09-02 단일세션 모델 반영)

> 2026-09-02 cmux 다패널 폐기 → 단일 메인 세션 + 필요 시 서브에이전트(Agent 툴) 모델로 전환.
> 컨텍스트 관리 대상은 이제 **패널들**이 아니라 **이 메인 세션 하나**다.
> **clear 는 맥락 손실 위험이 있어 신중해야 한다** — compact 와 용도를 명확히 구분한다(사용자 명시).

## 🔑 compact 와 clear 는 용도가 다르다 (혼동 금지)

| 도구 | 언제 | 효과 | 맥락 |
|------|------|------|------|
| **/compact** | **같은 작업이 길어질 때** (토큰 부풀음, 아직 진행 중) | 대화를 요약·압축하고 **계속 진행** | **보존** (작업 흐름 유지) |
| **/clear** | **한 작업이 끝나고 다른 종류로 전환**할 때 (스크린→도메인, FE→BE, 기능A→기능B 등) | 컨텍스트 완전 리셋, 새 출발 | **버림** (이전 작업 맥락 불필요할 때만) |

**핵심 원칙**: 진행 중 작업의 맥락은 잊으면 안 된다. 길어지면 → **compact**. 끝나고 성격이 바뀌면 → **clear**.
토큰이 많다고 무조건 clear 하지 말 것 — 작업이 안 끝났으면 **compact** 가 정답. 의심되면 clear 대신 compact(맥락 손실 < 토큰 절감, 안전 우선).

## 서브에이전트로 컨텍스트 부풀음 억제 (단일세션의 이점)
- 무겁거나 탐색적인 작업(대량 grep, 여러 파일 조사, 구현)은 **Agent 툴로 서브에이전트에 위임**하면 그 작업의 도구 출력이 메인 세션 컨텍스트에 안 쌓인다 — 자연스러운 컨텍스트 위생.
- 서브에이전트는 최종 요약만 반환하므로, 메인 세션은 결론만 받아 가볍게 유지된다. **긴 조사·구현은 기본적으로 위임을 우선 고려.**

## 트리거 규칙
### /compact (진행 중 압축)
- 같은 작업 진행 중 토큰이 부풀면(대략 120k+) compact 로 억제하며 계속.
- 여러 라운드 반복되는 긴 디버깅·구현은 중간중간 compact (맥락 유지한 채 가볍게).

### /clear (작업 전환 시)
- 조건 **모두** 충족: ① 현재 태스크 완결(결과가 파일에 영속: 워킹트리/커밋/문서), ② 다음이 다른 종류의 작업(다른 화면·도메인·기능·레이어).
- 즉 clear 는 "작업 경계 + 성격 전환"에서만. 같은 기능 이어서 하면 clear 아님(compact).
- clear 전 체크: "이 이전 대화 맥락을 이후 작업에서 다시 참조할 일이 없는가?" → 예 여야 clear.
