# Verification Evidence — DONE 은 증거로 말한다

> **P1 규칙 (2026-07-07 제정)**. 근거 사고: 2026-06-28 카카오 버튼 "세로 2배" 커밋 3개(95ab29b, 98d1461, 5aa9317)가
> 실제 렌더에는 한 번도 적용되지 않은 채 DONE 처리 → 사용자가 일주일 뒤 재보고, 픽셀 실측으로야 발견.
> "코드를 고쳤다" ≠ "동작이 바뀌었다". DONE 보고에는 반드시 **실측 증거**가 붙어야 한다.

## 변경 유형별 필수 증거

| 변경 유형 | DONE 에 필수 첨부 | 금지 |
|-----------|------------------|------|
| UI/스타일 (크기·색·레이아웃) | 시뮬레이터 **스크린샷** + 수치 변경은 **픽셀 실측** (`magick crop+색상행 카운트 /3 = dp`) | "코드에 반영했습니다"만 쓰고 끝 |
| UI 동작 (탭·네비게이션·모달) | 조작 전/후 스크린샷 or 화면 전환 확인 로그 | tsc/jest 통과만으로 DONE |
| API 신규/변경 | **curl 실측** (요청+응답 status/body) | 컨트롤러 코드 diff 만 |
| 버그 픽스 | **재현 → 픽스 → 재현 불가** 3단 확인 | 원인 추정만으로 픽스 선언 |
| 배치/스케줄러 | 수동 트리거 실행 로그 or 테스트로 시간 주입 | "다음 자정에 돌 것" |
| config/env | 실제 로드 확인 (`printenv`, 번들 grep, actuator) | 파일 수정만 |

## 절차 규칙

1. **런타임 검증 없이 DONE 금지** — 컴파일/타입체크/유닛테스트 GREEN 은 필요조건이지 충분조건이 아니다.
2. **검증 불가면 솔직하게 BLOCKED** — 검증 못 한 상태로 DONE 이라 쓰지 말고 "구현 완료, 검증 블록: <이유>" 로 보고
   (선례: 2026-07-06 FE-Dev 가 dose_logs 부재로 e2e 블록을 정직 보고 → 근본원인 발견으로 이어짐. 이게 정답).
3. **stale bundle 함정**: FE 는 검증 전 반드시 앱 재시작/번들 리로드 후 측정. Metro 가 살아있다고 새 코드가 실행 중인 건 아니다.
4. **자기 검증 + 교차 검증**: 작업자는 실측 첨부, CTO 는 독립 재측정(최소 스팟체크)으로 이중 확인.
5. 핵심 사용자 여정(등록→오늘 체크, 로그인→홈, OCR→약 매칭)을 건드린 변경은 해당 여정 **끝까지** e2e 1회.
