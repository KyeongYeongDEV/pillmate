# extract-approach — 어려운 문제 해결 후 사고 회로 박제 (레코더)

> AI TIP #5 적용 (2026-07-10). 어려운 문제를 풀면 그 **추론 과정을 자산으로** 남긴다.
> 요약이 아니라 원자화 — 이후의 (더 약한) 모델이 읽고 그대로 재적용할 수 있게 쓴다.

## 트리거 (자동 습관 — CTO·모든 패널)
다음 중 하나를 해결한 직후 **즉시** 학습 메모 1건 작성:
- 원인 규명에 2회 이상 가설이 필요했던 버그 (예: stale bundle vs 라이브 버그 구분)
- 인프라/도구의 비자명한 함정 (예: compose config 의 .env 자동로드)
- 반복될 수 있는 진단 절차를 새로 만든 경우 (예: 픽셀 실측)

## 메모 형식 (4줄 원자 노트 — 추후에 읽는 약한 모델용으로 작성)
```markdown
## <제목: 문제를 한 줄로>            ← 검색 가능하게
- **문제**: 한 줄 정리
- **접근**: 간단한 분해 단계 (1→2→3)
- **판단 질문**: 무엇을 하지 않았고, 왜 (배제한 가설과 배제 근거)
- **재사용 규칙**: 한 줄 (다음에 같은 증상이면 이것부터)
```

## 저장 위치 (원자화 — 긴 보고서 금지)
- **프로젝트 기술 문제**: `docs/architecture/learning-notes.md` 에 시간순 append (OCR 은 기존 `ocr-improvement-journal.md` 유지)
- **하네스/운영 문제**: 자동 메모리(`memory/`) 에 1노트 1통찰로 — 기존 규칙과 동일, `[[링크]]` 로 상호 연결
- 하나의 긴 보고서 ✗ → 저장되는 순간 잊혀진다. **1통찰 = 1노트.**

## 발화 방법
- CTO: 문제 해결 보고 직후 스스로 실행 (보고문 끝에 "📼 학습메모 저장" 한 줄 표기)
- 패널: DONE 보고에 4줄 형식 포함 → CTO 가 learning-notes.md 에 적재
