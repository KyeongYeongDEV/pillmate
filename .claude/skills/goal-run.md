# goal-run — 가짜 보고가 불가능한 목표 실행 루프

> AI TIP #4 적용 (2026-07-10). 목표는 결승선이며 작업의 흐름은 관중이다.
> 자율 실행(장기 루프·야간 실행) 시 이 패턴을 따른다.

## 두 가지 규칙
1. **결승선에 증명된 내용을 불어넣어라, 약속은 하지 마라** — "구현했다"가 아니라 green run(테스트 GREEN + 실측 증거)이 목표 달성의 유일한 판정.
2. **환경이 변할 때는 변하거나 벽시계를 봐라** — 같은 접근 반복 실패 시 접근을 바꾸고, 시간 예산 초과 시 멈춘다.

## 목표 작성법 (/goal 스타일)
- 목표 = **완성된 모습을 구체적으로**: "카카오 로그인이 시뮬레이터에서 홈 진입까지 성공하고, users 테이블에 신규 row 가 생기고, 그 증거(스크린샷+SELECT 결과)가 첨부된다"
- ❌ "카카오 로그인 고치기" (판정 불가) → 가짜 보고 가능
- 매 턴 끝마다 판정: **조건이 충족되었는가?** 아니오 → 다음 턴. 예 → 증명 첨부 후 종료.

## 안전장치 (비용 폭탄 방지)
- **턴 제한**: 자율 루프는 25턴 상한. 도달 시 무조건 멈추고 상태 보고.
- **락 가치 기준**: 목표는 10개가 아니라 **가장 가치 높은 2~3개**만 동시 실행.
- 같은 에러 3회 반복 → 루프 중단 + CTO/사용자 escalation (context-hygiene·Q 기준선 연동).
- 병렬 하위 에이전트 사용 시 서로 교차 검토 (한 에이전트의 PASS 를 다른 에이전트가 재실측).

## PillMate 적용
- 야간/무인 실행: `ScheduleWakeup` + 이 패턴. wakeup prompt 에 결승선 조건을 그대로 기입.
- 결승선 증거는 `verification-evidence.md` 형식 (스크린샷·curl·SELECT).
- deploy-gate 각 항목도 goal 형식으로 실행 가능 ("G2 완료 = dig 응답 + 443 접속 로그 첨부").
